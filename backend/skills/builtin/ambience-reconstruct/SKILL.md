# 意境重构（Ambience Reconstruction）

## 动态读取指令（最高优先级，不可跳过）

> **无论用户当前处于哪门课程、哪一页知识点，你必须先提取对应的上下文，再套用本工具的启发逻辑。**

具体步骤：

1. **先读上下文**。系统提示词的 `course_context` 区块里是用户当前所在页的
   正文——章节标题、学习目标、每个内容块的原文。它是你唯一的教材依据。
2. **确认落点**。从 `course_context` 里找出与用户问题直接相关的那个内容块
   （按标题与正文判断，不要只按关键词）。
3. **再上工具**。把该内容块的原文作为素材，套用下面的重构手法。

如果 `course_context` 是空的，或者用户的问题与其中任何内容都无关，
**明确说明**："当前课程内容里没有覆盖这个概念"，然后在说明边界的前提下
再给通用解释——不要假装在讲教材里没有的东西。

## 重构手法

把概念的**结构**翻译成一个学习者能想象的场景：

- **角色化**：让抽象的参与者变成有动机的人物。系统里的"请求"是一个
  急着拿到答案的用户，消息队列就是排队等着的顾客。
- **场景化**：给出具体地点与时间。「变量绑定」不是术语，而是"给一个
  永远会变的东西贴上不会变的标签"。
- **感官化**：给场景配上视觉或触觉线索，让人能"想起来"而不只是"读过"。
- **反例对照**：场景里安排一个"如果按错误理解会发生什么"的瞬间。

## 输出形态

1. 一句话给结论（沿用全局的house-rules）。
2. **意境场景**：一段具体、有画面感的叙述，3–5 句。
3. **回扣原文**：明确指出这个场景对应课程里的哪个概念，并引用原文片段。
4. 最小可验证的例子：把场景翻译回代码或步骤。

## 边界

- 场景必须**服务于理解**，不能喧宾夺主。比喻解释错了，比不给比喻更糟。
- 不许虚构课程里不存在的章节、公式或引用。
- 课程原文与你的场景冲突时，以课程原文为准，并指出冲突。
